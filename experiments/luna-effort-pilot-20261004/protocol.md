# Luna effort workflow pilot — frozen before dispatch

Question: with unchanged workflow 0.2.0, what happens on the same three small engineering cases when gpt-6-luna reasoning effort is low versus high?

Six cells: aggregation, conflict, tickets × low/high; one attempt per stage, one run per cell. No statistical inference, general ranking, or causal workflow-benefit claim. No no-workflow control. Same model identifier; only requested effort intentionally differs. We cannot pin/expose a sampling seed, temperature, model snapshot, internal token budget or billed token count through this tool. Do not invent these values.

Each cell enters tasker → researcher → planner → implementer → reviewer. The frozen controller must authorize each dispatch. A block, invalid artifact, user decision, upstream return, invocation failure or missing output ends that cell; never skip ahead or silently repair artifacts. The conflict cell should legitimately end before implementation. No retry across invocations. Self-correction inside an implementer's original invocation is allowed by the workflow. Wall time includes tool latency and is descriptive only. Timeout per stage is 10 minutes; any interruption counts as timeout, not model failure. Launch paired stages together when both are ready. Alternate first launch by case: aggregation low first, conflict high first, tickets low first. No outcome-driven changes to launch order.

Every tested stage is a fresh collaboration.spawn_agent invocation with fork_turns=none, explicit gpt-6-luna model and low or high effort. The root/stage AGENTS, direct input artifacts, explicitly authorized solution.py/smoke.py/examples.json/policy.txt and controller-generated revision/input fingerprints are the only task-specific inputs. Agents may use local shell/file tools for authorized reads/writes and implementation checks. They may not use graph, network, other agents, private evaluation, peer outputs, or prior chat. Root has verified graph project absent and reads exact authorized sources instead. All stages own only their artifact; implementer additionally owns solution.py. Agents must write the artifact themselves; orchestration snapshots raw bytes with no JSON extraction, field insertion or corrections.

Fresh model invocation is real; filesystem isolation is a directory allowlist, not an OS-enforced per-agent sandbox. Ambient platform instructions and globally exposed tools still exist. No claim of adversarial isolation or complete raw tool-transcript capture. Preserve full dispatch prompt, return metadata, final message if exposed, stage artifact bytes, controller output, public smoke logs, and independent evaluation logs. Main orchestrator does not assist models after dispatch or reveal expected answers.

Primary cell success is joint: (a) original semantic task is satisfied under independent frozen evaluation, including read/write scope, and (b) correct workflow terminal outcome. For aggregation/tickets this requires all hidden test groups pass, protected files intact, and controller completed. For conflict it requires a valid explicit tasker requirement-conflict block with evidence identifying both mandatory incompatible outputs and no source edits. A later correct block is recorded but does not satisfy the strict early-block primary criterion. Private evaluator checks structural evidence for the conflict, followed by main-agent reading for semantic faithfulness.

Report separate axes: hidden test groups and denominator; schema/lineage gates and attempted stages; terminal stage/reason; requirement loss or incorrect success claim; protected-file/scope checks; elapsed wall time. A passing public smoke check alone is not task completion. Incorrect success is any implementer or reviewer success declaration when independently evaluated semantic correctness or protected-file checks fail. The automated score flags a candidate; main agent must inspect evidence before labeling it confirmed.

Complete model input is archived in each dispatch prompt; initial task and fixture bytes are identical across each pair. Directory, UUID and input hash values necessarily differ downstream. Later model outputs are endogenous, not a change to the intervention. Private evaluate.py, held-out test vectors and peer results are withheld by instruction and never in the payload. Recount runs evaluate.py without model calls. Frozen source and task files are hashed in manifest.json; runtime lineage covers only normal workflow inputs. Tool schemas/system prompts and provider internals are not captured or claimed frozen.

All reusable artifacts and results stay under this directory. Main experiment administration also has tasker/researcher/planner/implementer/reviewer records under the repository share/luna-effort-pilot-20261004; those administration stages use same-invocation fallback and are not part of the model comparison. No product/rule/README modifications or Git operations. Keep raw evidence; delete only task-created caches and scratch.
